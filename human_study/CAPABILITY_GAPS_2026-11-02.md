## 2. 處置紀錄（依優先級）

每項：**依據（文獻／原始碼／專家做法）→ 可行性 → 做了什麼 → 對其他能力的影響**。

### 2.1 無效狀態濾除（NUM-a、OBS-a、OBS-g）✅
- **依據**：FEBio 原始碼 `FECore/FETimeStepController.cpp`：`CheckMustPoints` 回傳 `tmust − t`，`m_dtp` 不含 must-point 調整——微步是設計行為，不是 bug，所以解法在後處理。準靜態分析的慣性可信度準則（Abaqus 慣例：動能 < 5% 內能）在此無法直接取得，改以狀態層級濾除。
- **可行性**：極高（純後處理）。
- **做法**：`biocage-evo/methods/e03_mu_req.py` 新增 `filter_rows`／`target_bracket`／`lerp`／`state_at`：
  (a) dt < 1e-4 的狀態丟棄；(b) 孤立尖峰——與鄰點預測（前一有效點與下一原始點的線性內插，或最後兩有效點外推）差 > max(0.15×目標, 1×預測) 的狀態丟棄；(c) 首列 > 3×目標丟棄。
  規則經過三版：比值法（> 2×）在上升段初期連鎖誤判整段（p027、p088、p130…）；斜率外推 + 變號法仍在伸展視窗的合法過零處誤判；鄰點預測法通過全部 10 個自測模式（p060 微步、p100 尖峰、p027 緩升、p015 爆掉、伸展過零、小首列）。
- **掃描結果**（474 視窗）：1 個微步、21 個尖峰視窗；**3 個舊判定曾依賴垃圾狀態**（split2 p015 extension、p027 extension；fric p060 LB_left）→ 改判未達標（R02：不淘汰，重定振幅）。
- **影響**：[速度] 0；[多元] 0；[物理] 無變更。e04/e05 新增 `--test`。

### 2.2 目標力矩插值（OBS-b）✅
- **依據**：取樣過衝只是取點方式，線性插值在兩個相鄰收斂步之間（力矩-轉角曲線平滑）誤差遠小於過衝。
- **做法**：e04 在包夾兩態各算一次指標再線性插值；e05 取「包夾下態之前所有有效狀態的最大值」與插值之大者。
- **驗證**：p062 extension 滑移上限 0.1463 → 0.1383 mm（連續 run 在 1552 N·mm 時 0.1339）、AR_left 0.2090 → 0.2016（連續 run 0.2006）、flexion 0.1155 → 0.1114。**NUM-07 的 split vs sequential 殘差其實就是過衝**，插值後六向一致 ≤ 1%。
- **影響與結果**：全批重算完成（276 視窗、0 錯誤；舊結果保存於 `split_pre_interp_20261031/`）。234 個雙方達標的視窗：mu_squeeze 中位數 −0.4%、滑移上限 −3.4%（過衝修正如預期）。13 個 |Δmu| > 20% 的視窗全可解釋：10 個是舊判定用了尖峰狀態（p100 LB_right 用 6799 N·mm 的垃圾點算出 0.043，現為 0.122；p092 AR_left 0.125 → 0.036；p082、p088、p015、p052、p061、p051 類似），3 個是 mu < 0.01 的絕對變動 ≤ 0.002。**名單變化：73/63/12 → 72 pass／63 fail／13 open**，唯一移動的是 p027（見 2.7）。

### 2.4 旋轉協定的數值收斂（NUM-c）🧪
- **依據**：Henninger et al. 2010（Proc IMechE H 224:801）引述脊椎節段研究以「加密後解變化 < 5%」為收斂準則；時間離散需另行驗證。FEBio 自動罰則 = penalty × E/h（h = 接觸元素厚度），所以 0.1 mm 層的罰則剛度自動加倍——用 penalty 5 補償，使絕對接觸剛度與 0.2 mm 基準相同（不改 h14）。
- **做法**：p062 四組，類別與 job：`numconv_dt`（physio_dt 0.025；physrotNdt_）、`numconv_pen05`／`numconv_pen20`（physrotNp05_／Np20_）、`numconv_hz01`（h12 HZ 0.1 mm 網格 `meshconv/cage_A_axial_mix_d0.500_HZ0.1.npz`，46 層、106k hex；penalty 5；physrotNhz_）。振幅取 split2 p062（六向皆達標）。
- **判讀**：與 split2 p062 的插值結果比 mu_squeeze、單面滑移、持續壓縮：差 ≤ 5%（網格、罰則）、≤ 2%（時間步）則 NUM-01/03/05 通過。mu 的相對差只在絕對差 > 0.005 時才計（p062 extension 的 mu ≈ 0.014，+20% 只是 0.003；`numconv_compare.py MU_ABS`，提案）。
- **代價**：約 4 × 0.5–1 GPU-h（實際在 CPU 上跑，各 1–1.5 h）。
- **第一次結果（16:45，舊濾除）**：四個變體在 5/6 個視窗都在門檻內（slip 差 ≤ 2.3%、mu 差 ≤ 3.3%、持續壓縮差 ≤ 0.11 pp）；唯一一致超出的是 **extension**（slip −5.5～−7.5%、mu +4～+20%），而且四個變體彼此只差 2%（slip 0.128–0.131）——離群的是**基準**（0.1383）。逐態軌跡證明：基準在 t=3.9455 的那一態是失敗後重試的步（log：Retry attempt 1，dt 0.05→0.04545），驅動力矩讀 1360 而鄰點插值為 1535，slip／mu／N 卻與鄰點一致；C3pot.txt 同一態的剛體力矩 My = −184 N·mm（其他態 < 0.3），正好等於缺口。基準按力矩軸排序後在 |M|=1500 的 slip 是 0.1293，與變體 0.1292／0.1308／0.1280／0.1299 一致（±1.1%）。pen20 AR_left 的 −14% 同理（重試步，殘差 300，之後力矩非單調）。→ 處置 2.9。
- **最終結果（18:00，NUM-14 濾除後重算；`biocage-evo/results/method/numconv/compare.json`）**：四組全部通過。

### 2.9 剛體動態殘差：第二層無效狀態（NUM-14；NUM-a 根因）✅
- **現象**：2.4 找到的重試步偽力矩。全部 474 個視窗、6090 個狀態統計 C3pot.txt 的剛體反力矩 |M_rb|：中位數 1.0 N·mm、90 百分位 15、99 百分位 346；> 30 N·mm（目標的 2%）的 356 個，其中 75 個在重試步、37 個是視窗第一態（起步暫態）、其餘是接觸顫動；**37 個包夾態受污染，4 個視窗的「達標」只靠一個殘差 > 30 的末態**。
- **這個量是什麼**：FEBio 的 `rigid_body_data Fx..Mz` = `FERigidBody::m_Fr/m_Mr`，在 `FEResidualVector` 累加附著節點的殘差貢獻、跟隨負荷（`FERigidFollowerForce`）與關節力（`FEGenericRigidJoint`）。每個收斂的準靜態態都是 (0, 0, −100, 0, 0, 0)；偏離量就是剛體的動態（慣性）殘差。驗證：對大尖峰用 `M_drive − M_rb(軸向)` 修正，p052 +245% → +0.4%、p061 +224% → −11%、p051 +237% → +0.6%、p093 +118% → −1.0%、p062 −11.4% → +0.6%、p142 +32% → −0.5%、p145 +34% → −0.0%、p101 +15% → +0.2%。**尖峰就是被驅動剛體的慣性暫態**（密度 ×1000 的質量縮放放大了它）。
- **為什麼不修復只丟棄**：在不穩定視窗裡修正不可靠（196 個殘差態：drive 誤差中位數 3.2%，修正後 5.1%），因為鄰點本身也被擾動。丟棄 = 包夾退到鄰態，誤差只是插值間距（≈ 一步，< 2%）。
- **為什麼不用力殘差**：先試過「力偏離跟隨負荷 > 2%（2 N）」也算無效：多丟 157 個態、多翻 13 個視窗；但這些態（p092 flexion 4.7–7.2 N、p130 extension 7.2 N、p083 LB_left 3.7 N）的 slip／mu／N 軌跡平滑到 < 0.5%、力矩殘差 < 30——那是收斂鬆弛，不是暫態。**規則只用力矩殘差（2%×目標 = 30 N·mm）；力殘差記錄在 `window_check.rb_fres_max`。**
- **為什麼不收緊平滑度門檻**：rel 0.10／abs 0.05 會動到 75 個視窗、103 個態，多數在視窗起始的過零段，無法與合法曲率區分。
- **實作**：`e03.rb_rows`／`dyn_residuals`／`filter_rows(..., dyn, Fref)`（理由 `'dyn'`，附殘差值）、`DYN_M=0.02`、`DYN_F=None`；`window_check` 加 `n_dyn`、`rb_res_max`、`rb_fres_max`；e04／e05 自動沿用；h28 重定振幅、h31 `window_check`、h34 掃描同規則；collect_split 的 unstable 規則加「有丟棄且未在有效態結束（complete False）」。自測：p062 重試態被丟、包夾退到 (3.9, 3.99182)、無 C3pot.txt 時行為不變、3 N 力殘差只記錄。
- **影響**：h34 重掃：158/474 視窗有 dyn 態（337/5278 = 6.4%）；**11 個視窗由「達標」變「未達標」**（生產批 5：p088 AR_left、p107 AR_right、p117 AR_right、p015 AR_right(split3)、p082 AR_left(split4)，全部 complete False、末段殘差 47–9135）。生產批 123 個視窗的判定狀態改變（多數只是包夾退一步），已封存到 `results/method/split_pre_dyn_20261102/` 並重算；37 個先刪後比對不變的已還原。
- **重算結果（18:00）**：276 視窗 0 錯誤，**70 pass／62 fail／16 open**（原 72/63/13）。只有 3 個設計移動：p082、p107 由 PASS → open（`[數值]/unstable-window`：AR_left／AR_right 末段崩潰，達標只靠殘差 688／763 的末態）；p003 由 fail（compression-peak-lowerbound）→ open（extension 末段崩潰，下限不可信）。p027 維持 open。其餘 145 個設計的 class 不變；判定依賴的 mu／slip 變動都在插值間距內。unstable-window 共 4（p003、p027、p082、p107），各需重跑一個視窗。
- **附帶發現**：p082 與 p088 是同一設計（2.10），p088 的 AR_left 在另一回合乾淨達標 → PASS，p082 卻因 split4 的 AR_left 崩潰而 open。同一設計的證據應合併（T26 的第二部分：collect_split 以參數去重），合併後 p082 = PASS。
- **代價**：純後處理；重算 123 視窗約 1 h CPU。

## 3. 解法之間的矛盾

### 3.1 [速度] 少存狀態 vs [數值]／[觀測] 需要可信的包夾狀態
- `plot_level PLOT_MUST_POINTS` 看似最省（每視窗 10 個狀態），但 FEBio 源碼證明 must-point 狀態正是以微步抵達的狀態——在慢速動態下就是偽力矩狀態；而且插值需要跨過目標的兩個相鄰收斂步，事前不知道在哪。
- `plot_stride`／`plot_range` 只對固定步長有效（FEBio 手冊），我們用自動步長。
- **可行的折衷**：視窗照舊全部輸出，結束後由後處理把 xplt 精簡成「包夾兩態 ±1、首末態」（xplt 區塊格式可直接複製 STATE 區塊，不必解壓）。效果 123 MB → 約 25 MB/視窗。**未實作**：需要 PI 決定保留政策（今天的全批重算只因所有狀態都還在才做得到）。

### 3.2 [數值] 骨元素翻轉的修法 vs [速度]、[多元]
- 候選修法：更小的跟隨負荷步長、`max_retries` 提高、擴增拉格朗日、軟層厚度方向 2 層、h32 皮層等效律。
- 摩擦插入 run 現在每個 4.8 GPU-h 才失敗；每個修法都要重跑才知道；厚度 2 層使 cage 自由度加倍；h32 改變模型需全套重驗（NUM-07/08、PHY-05）。

### 3.3 [多元] 可計算率 vs [物理] 細節保真（PI 不均質化規則）
- 最便宜的修法（把 0.2 mm 軟層均質化或加硬）被規則禁止；合規修法都落在 3.2。

### 3.4 [觀測] R02（未達標永不淘汰）vs [速度] 回合數
- 每次重定振幅多一回合（每設計約 10 min GPU）；濾除尖峰後會多出幾個「未達標」視窗（p015、p027 extension）需要再跑。h29 一般化後可自動串接。

### 3.5 [數值] 自動罰則 vs 網格收斂的可解釋性
- 用 penalty 5 補償 0.1 mm 層的自動罰則是近似（FEBio 的厚度估計 = 體積/面積，剛好反比於 h，但 E 的取法未逐行核對）。乾淨的做法是 laugon=1 讓結果對罰則不敏感——但那是 BUILD 變更，所有既有判定都要重驗。

### 3.6 [速度] 磁碟配額 vs [觀測] 可重算性
- 規劃配額 500 GB；al_v2 現有 1.2 TB，其中約 60% 是視窗 xplt。刪掉就不能再做今天這種方法修正後的重算（今天就重算了兩次：插值、剛體殘差）。

### 3.7 [速度]／[多元] 質量縮放 vs [數值] 慣性暫態
- 慢速動態用密度 1e-6 t/mm³（水的 1000 倍）讓接觸起始與插入算得過去（[速度]、[多元]），代價是每次步長切割／重試都留下與目標同量級的慣性力矩殘差（2.9），以及視窗起步的暫態。
- 無悔手段 = 2.9 的濾除（純後處理）。根治手段都要重驗：密度降 10–100 倍（暫態等比例縮小，但接觸起始可能算不過）、改靜態（32 個視窗是動態失敗後靜態救回的，反向也有失敗）、或重試後強制一步回到原步長再記錄。要 PI 決定是否投入（第 4 節第 7 項）。

## 4. 無法在平台端解決、需要與 PI 討論

1. **骨元素翻轉（NUM-06）**：12/13 黏死插入失敗、2/3 摩擦插入失敗都含 C3/C4 皮質骨翻轉；視窗裡 C3 皮質骨翻轉 14663 條。這是求解穩健性問題，但每個候選修法（3.2）都要花數 GPU-h 試、且可能改變既有判定。要決定：投入多少機器時間在摩擦插入的穩健性，或 gate 4 只做 4 個設計就下結論。
2. **家族 B 幾乎算不下去（DIV-04，新發現）**：不可計算設計 8/9 屬家族 B（平面 + 軟墊）、7/8 屬 gradient both、集中在低 E_soft。其中 10 個在跟隨負荷下最後狀態壓縮已 > 30%（下限超標）。兩種解讀：(a) 家族 B 在 100 N 下本來就不可行（設計結論）；(b) 平台對薄軟層不穩健（平台結論）。前者 = T05 以下限判 fail，後者要 3.2 的投入。這決定了 [多元] 的合格標準怎麼定。
3. **材料數據（PHY-06、T04）**：bench 之前無解；壓縮 15/25% 規則的敏感度報告屬次要 [泛化]。
4. **磁碟政策（3.1、3.6）**：是否同意「視窗 xplt 事後精簡為包夾態」與「配額門檻」；以及現有 1.2 TB 哪些移到 NAS。
5. **e06 門檻（OBS-f）**：依 Smit 的 14 MPa/decade，6 個月壽命約需應力 ≤ 短期強度的 18%（我的外推，非作者建議；濕態更低）。要定：以濕態降伏的 25%、18% 或其他值作為 pass 門檻。
6. **推出守門值 135 N（PHY-d）**：文獻不支持通用值。選項：ASTM 式測試（100 N 預載 + 泡棉）的相對比較、或以生理剪力（Moroney 1988）重新推導。
7. **慢速動態的偽狀態（NUM-a 根因，已定位）**：根因是被驅動剛體的慣性殘差（2.9）：重試步、視窗起步、接觸顫動時，關節力矩含與目標同量級的慣性成分；158/474 視窗有這類狀態，11 個視窗的「達標」靠它。濾除（兩層：微步、剛體殘差 > 2%）之後判定安全，但這是症狀處理。要決定：(a) 接受濾除為常規（零成本，已實作）；(b) 投入根治（3.7：降密度、改靜態、重試後回步），每個選項都要重驗既有判定。我建議 (a)，並把 (b) 列為 gate 4 之後的題目。
