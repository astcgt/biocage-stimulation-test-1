# 稽核發現待辦清單（2026-11-01）

依嚴重程度排序。每一條都標上**能力標籤**（平台的目標，PI 2026-11-01 指定為標籤；2026-11-02 增 [數值]，[泛化]／[時程] 為次要）：

| 標籤 | 意思 |
|---|---|
| **[物理]** | 物理真實性（Validation）：模型方程描述的東西要像真的脊椎和真的 cage |
| **[數值]** | 數值正確性（Verification）：方程要被正確地解出來（網格、時間步、接觸演算法、近似、求解器）。PI 2026-11-02 新增 |
| **[速度]** | 模擬速度：同樣的答案用最少的機器時間得到 |
| **[觀測]** | 只觀測我們關注的目標，而且量得正確、完整、可追溯 |
| **[多元]** | 容納多元設計：各種形狀與材料配置都算得下去，且不靠簡化掩蓋設計細節 |
| [泛化] | 次要（暫緩）：結論在病人、材料、摩擦、置入、規則門檻變動下是否穩健 |
| [時程] | 次要（暫緩）：支撐期 0 到 16 週以上的時間演變（降解、蠕變、biodisc 成熟、疲勞） |
| [設計] | 不是平台的問題：設計本身該被淘汰 |
| [決定] | 規則還沒定，需要 PI 決定 |
| [流程] | 不屬於四個能力：治理、文件、版本控制 |

「平台 vs 設計」判定規則和各能力之間的妥協關係寫在 `PLATFORM_CAPABILITIES.md`；每條 T 對應的可量測檢查（PHY-/NUM-/SPD-/OBS-/DIV- 編號）在
`platform_capabilities.json`，計分表 `CAPABILITY_SCORECARD.md` 由 `scripts/8_audit/h33_capability_audit.py` 產生。
2026-11-02 依 [數值] 重新標籤：T01、T02、T14、T17、T18。
每條的格式：**現象（白話）→ 證據（檔案）→ 分類 → 怎麼修 → 會不會影響其他能力 → 狀態**。2026-11-02 的處置紀錄與矛盾清單在 `CAPABILITY_GAPS_2026-11-02.md`。

## 嚴重度 1：結果可能是錯的，或主結論沒有支撐

### T01 [物理][數值][觀測] 真實摩擦對照（gate 4）沒有得到有效的對照結果
- **現象**：整個篩選的「會不會滑出」是用「cage 黏死在骨頭上」的簡化模型算出來的（所需摩擦係數 mu_req）。
  為了檢查這個捷徑可不可信，10-31 排了 7 個通過的設計用真實摩擦（摩擦係數 0.35）重跑。結果：
  1. 3 個設計（p048、p084、p115）在插入／加 100 N 跟隨負荷的階段就算不下去：p048 在 t 3.009 停，
     1957 個元素翻轉（cage 軟層 920、C3 皮質骨 502、cage 硬相 447、C4 皮質骨 87）；p084 在 t 3.045 停
     （cage 軟層 792、C3 皮質骨 397、C4 皮質骨 166）；p115 在釋放階段 t 2.59 停（cage 軟層 66 個）。
     這 3 個設計在黏死版本全部六個方向都算完了，所以不是設計的問題，是摩擦接觸算不穩。
  2. p109 的屈曲與伸展視窗失敗（動態與靜態重試都失敗；翻轉以 C3 皮質骨為主：232／201 個）。
  3. 跑完的 4 個設計（p060、p062、p109 四個方向、p125）**沒有任何一個視窗真正達到 1.5 N·m**：
     摩擦版本沿用了黏死版本的旋轉振幅（兩份 `_params.json` 的 `physio_rot_rad` 完全相同），但真實摩擦下
     cage 不再傳遞剪力與扭轉，節段變軟，同樣的轉角只產生 0.5–1.2 N·m（例：p062 屈曲 922 N·mm，黏死 1746 N·mm）。
     所以「黏死 vs 摩擦」的比較不是在同一個負荷下做的，不能下結論。
  4. 唯一顯示「達標」的 p060 LB_left 是假的（見 T02）。
- **證據**：`human_study/al_v2/physio_fric/*/case.log`、`w_*/drive.txt`；
  `biocage-evo/results/method/fric/compare.json`（今天由 `ops/fric_compare.py` 產生）；`work/ops/logs/fric_compare_20261101.log`。
- **分類**：平台能力不足。[數值]：摩擦接觸的求解穩健性（插入與跟隨負荷階段的元素翻轉，含骨元素；NUM-06）；[物理]：gate 4 本身（PHY-05）；
  [觀測]：振幅重定目標（h28 的 retarget）假設節段剛度與上一回合相同，對摩擦版本不成立。
- **怎麼修**：
  (a) 摩擦視窗依 `drive.txt` 的實際反力矩重定振幅（約 ×1.5–2.5）再跑一回合（h28 的機制，但 prev 指向摩擦 run）。

      接觸罰則調整、h32 接觸皮層等效律（T08）。
  (c) e04 的「達標」判定不得依賴單一微步（T02）。
- **影響其他能力**：[速度] 摩擦 run 每設計 2–4 h（黏死 23 min）；[多元] 若引入接觸皮層等效律，所有既有驗證要重做；

## 名詞解釋

**兩個專案資料夾**
- `biocage_simulation_test_oct2026`（舊 repo，2026-11-01 由「biocage stimulation test 1」改名）：人體 C3-C4 模型、cage 建模、排程、150 個設計的篩選結果。
- `biocage-evo`：自由形態演化專案；也放判定指標程式 e03/e04/e05 與彙整器 `ops/collect_split.py`。

**程式（h = 舊 repo 的腳本編號，e = evo 的指標程式）**
- h12 產生 cage 網格（0.2 mm）；h14 組裝一個 FEBio 案例；h30 把案例拆成「插入 run + 6 個獨立視窗」；h31 執行拆分 run（含動態失敗後的一次靜態重試）；
  h24 起跑前檢查（模型是否由現行程式與設定建出）；h19 排程器；h23 看門狗；h18 GPU 執行；h28 依前一回合重定振幅並排隊；h29 自動串接回合；
  h32 接觸皮層等效律原型；h22 主動學習。
- e03 所需摩擦係數 mu_req（3-D 曲面版）；e04 滑出模式篩檢（mu_squeeze、單面滑移上限、cage 剛體平移）；e05 軟相壓縮檢查；
  `collect_split.py` 從每個 run 的結果檔彙整成 pass／fail／open。
- `fric_compare.py`、`degr_compare.py`：今天跑的兩個比較腳本（真實摩擦 vs 黏死；軟相降解敏感度）。

**模型與程序**
- 黏死（tied）：cage 與骨面黏合、不能滑的簡化；真實摩擦：可滑動接觸，摩擦係數 0.35。
- expand 插入：cage 建成 0.8 倍高度，撐開時膨脹回設計高度（數值上的插入法）。跟隨負荷：100 N 軸向壓力。
- 旋轉控制視窗：六個方向（屈曲、伸展、左右側彎、左右軸向旋轉），轉 C3 直到反力矩達 1.5 N·m，視窗停在 t 4.0 的峰值。
- split2／split3／split4：第一／二／三回合（工作前綴 physrotT_／U_／V_）；physrotFr_ 真實摩擦批次；physrotG5／G2／G1 降解批次（E_soft × 0.5／0.2／0.1）。
- 慢速動態：密度放大 1000 倍、rho_inf 0 的準靜態動態分析，用來越過接觸起始的收斂困難。
- 元素翻轉（negative Jacobian）：網格元素被壓到翻面，求解器無法繼續。must point：FEBio 必須在指定時刻停一步。
- E_soft／E_hard：軟相（PLCL 50:50）與硬相（PLCL 85:15）的彈性模數；家族 A（貼合端板）／B（平面 + 軟墊）；gradient axial／radial／both。
- p0xx：150 個主動學習設計點的編號。

**檔案**
- `case.feb` 輸入；`case.log` 求解紀錄；`case.xplt` 繪圖輸出（後處理讀這個）；`case.dmp` 重啟檔；`drive.txt` 驅動關節的力／力矩歷程；
  `*_params.json` 建模參數；`preflight.json` 起跑前檢查結果；`current_settings.json` 全研究設定（分「類別」）。
- `results/method/split/*_merged.json` 目前的合併判定；`e04_rot/failed_runs_lastJ.json` 失敗 run 的最後狀態表。

**人與角色**
